# CYJ 炭素会計アプリ　メンバー向けガイド

Climate Youth Japan（CYJ）の活動で出る温室効果ガスの排出量を記録・集計するためのウェブアプリです。これまで使っていた Excel テンプレート（CYJ_Official_Template）の代わりに使います。

- **アプリのURL**：https://myanase0707-ux.github.io/Carbon-Accounting/
- **ログイン**：管理者から発行されたメールアドレスとパスワードでログインします（1人1アカウント）。

---

## 1. このアプリでできること

- 活動データ（移動・宿泊・食事・オンライン会議など）を入力すると、排出量（kg-CO₂e）が自動で計算されます。
- 排出係数は候補リストから選ぶだけです。係数を自分で探したり、手入力したりする必要はありません。
- ダッシュボードで、月別・カテゴリ別・活動別の排出量をグラフで確認できます。
- 入力したデータは団体のデータベースに保存され、メンバー全員で同じデータを見られます。

## 2. 使い方

### ログイン
アプリの URL を開き、メールアドレスとパスワードを入力します。共用のパソコンを使ったときは、終わったら右上の「ログアウト」を押してください。

### 入力（「入力」タブ）
1. **日付・活動名・チーム**を入れます。活動名は「春合宿」「運営MTG」など、集計したい単位でそろえてください。過去の活動名は入力候補に出ます。
2. **カテゴリ**（交通・宿泊・会場・食事・オンライン会議など）を選びます。
3. 表示された**排出係数の候補**から1つ選びます。出典も一緒に表示されます。
4. **活動量**を入れます。
   - 交通：片道の距離（km）と人数。往復なら「往復」を選びます。
   - 宿泊：泊数と人数
   - オンライン会議：会議の時間（分）と参加人数
   - 食事・備品：金額（円）
5. 計算結果がその場で表示されるので、確認してから「保存する」を押します。

保存したあとも日付・活動名・チームは残るので、同じ活動のデータを続けて入力できます。

### 確認・修正（「データ一覧」タブ）
- 検索やカテゴリ・月・確認状況で絞り込めます。
- 行をクリックすると編集画面が開きます。修正や削除はそこから行います。
- 「CSVでダウンロード」で一覧を Excel などで開けるファイルに書き出せます。

### 集計（「ダッシュボード」タブ）
年度・チーム・活動名で絞り込んで、合計排出量とグラフを確認できます。報告書の作成に使ってください。

### 排出係数（「排出係数」タブ）
係数の一覧と出典を確認できます。係数の追加・変更は、担当者が出典を確認してから行います（「6. 運用ルール」参照）。

## 3. 計算の仕様

**排出量（kg-CO₂e）＝ 活動量 × 排出係数**

活動量は、入力した値からアプリが次のように計算します。

| カテゴリ | 入力するもの | 活動量の計算 | 単位 |
|---|---|---|---|
| 交通 | 片道の距離・人数・片道／往復 | 距離 × 人数 × （片道1／往復2） | 人km |
| 宿泊 | 泊数・人数 | 泊数 × 人数 | 人泊 |
| オンライン会議 | 時間（分）・参加人数 | 分 ÷ 60 × 人数 | 人時間 |
| 食事・備品など | 金額 | 金額そのまま | 円 |
| 電力・廃棄物 | 使用量・重量 | 入力値そのまま | kWh・kg |

- **計算式はアプリの中にあります。** 入力欄に式がないので、Excel のように式が壊れることはありません。
- **保存したときの係数を一緒に記録します。** あとで係数マスタの値を変えても、過去に入力したデータの排出量は変わりません。
- **オンライン会議の係数**（0.0655 kg-CO₂e/人時間）は、旧テンプレートの計算式（PC製造分の按分＋通信。Faber 2021）を1つにまとめたものです。
- **確認状況**は次の5つです。
  - 未確認：入力しただけの状態
  - 仮置き：数値が仮のもの（距離の概算など）
  - 要確認：誰かに確認してほしいもの
  - 確定：確認が済んだもの
  - 対象外：記録は残すが、集計には含めないもの

## 4. システムの構成

| 役割 | サービス | アカウント |
|---|---|---|
| 画面の公開 | GitHub Pages | 団体の無料アカウント |
| データの保存・ログイン管理 | Supabase（データベース） | 団体の無料アカウント |

- GitHub は画面（プログラム）を配るだけです。**入力したデータは GitHub には保存されず、Supabase のデータベースに保存されます。**
- GitHub のリポジトリは公開ですが、そこにあるのは画面のプログラムだけです。活動データは、ログインしたメンバーしか見られません。
- 画面を更新しても、データは消えません。

## 5. セキュリティとアカウント管理

### メンバーへのお願い
- **アカウントは1人1つです。** パスワードをほかの人と共有しないでください。誰が入力したかが記録されます。
- パスワードを人に教えたり、チャットやスプレッドシートに書いたりしないでください。
- 共用のパソコンでは、使い終わったら必ずログアウトしてください。
- パスワードを忘れたときや、漏れたかもしれないと思ったときは、すぐに管理者に連絡してください。
- 今のアプリには、自分でパスワードを変える画面がありません。変更したいときは管理者に依頼してください。

### 管理者の手順

#### 新しいメンバーを登録する
1. 団体のアカウントで Supabase の管理画面にログインし、炭素会計のプロジェクトを開きます。
2. **Authentication → Users → Add user → Create new user** を選びます。
3. メンバー本人のメールアドレスを入力します。
4. パスワードを発行します。
   - パスワード管理ソフトの生成機能などで、**12文字以上のランダムな文字列**を作ります。
   - 名前や誕生日など、推測できるものは使いません。
   - 他のメンバーと同じパスワードを使い回しません（**1人1パスワード**）。
5. **「Auto Confirm User」にチェック**を入れて作成します。チェックしないと、確認メールの処理が終わるまでログインできません。
6. メンバーに伝えます。
   - アプリの URL とメールアドレスは、通常の連絡で伝えて構いません。
   - **パスワードは別の経路で伝えます**（例：URL はメール、パスワードは LINE の個別メッセージや口頭）。グループチャットには書きません。
7. 本人がログインできたことを確認します。

#### パスワードを再発行する
1. **Authentication → Users** で該当メンバーを開きます。
2. 新しいパスワードを設定します。または、いったん削除して上の手順で作り直します。
3. 新しいパスワードを、上と同じく別の経路で伝えます。

#### メンバーが抜けるとき
**Authentication → Users** で、そのメンバーのユーザーを削除します。その人が入力したデータは残ります。

#### 最初に一度だけ確認する設定
- **新規サインアップを無効にする**：Authentication の設定で「Allow new users to sign up」をオフにします。これで、管理者が登録した人しかアカウントを作れません。
- **データベースの権限**：ログインしたメンバーだけが読み書きできる設定（Row Level Security）になっています。設定用の SQL は `supabase/schema.sql` にあります。

### 団体アカウントの管理
- GitHub と Supabase の団体アカウントには、**2段階認証を設定**してください。
- 担当者の交代に備えて、**管理者は2人以上**にし、ログイン情報の引き継ぎ方法を決めておいてください。
- Supabase のキーのうち、`index.html` に書いてよいのは **publishable（anon）キーだけ**です。**secret キーと service_role キーは、どこにも書かず、誰にも共有しないでください。** これらがあると、すべてのデータを読み書き・削除できてしまいます。
- 活動データの入った `demo.html` や `seed.sql` は、公開リポジトリに置かないでください。

## 6. 運用ルール

- **入力はなるべく早めに。** 活動が終わったら、その週のうちに入力するのが目安です。
- **根拠を残す。** 距離の出し方（経路検索の結果など）や仮定は、「内容」や「メモ」に書いてください。
- **係数の追加・変更は担当者が行います。** 出典名・URL・年度を必ず登録します。係数を変えても過去のデータは変わらないので、過去分も直す必要がある場合は担当者に相談してください。
- **定期的にバックアップを取ります。** 担当者は、年度末や報告書の作成前に「データ一覧 → CSVでダウンロード」で書き出して、団体のドライブに保存してください。
- **無料プランについて**：Supabase の無料プランは、しばらくアクセスがないとプロジェクトが一時停止することがあります。ログインできなくなったら管理者に連絡してください。管理画面から再開すれば、データは残っています。

## 7. 困ったとき

| 状況 | 対処 |
|---|---|
| ログインできない（`Invalid login credentials`） | メールアドレスとパスワードを確認し、だめなら管理者に再発行を依頼する |
| `Email not confirmed` と出る | 管理者が「Auto Confirm User」にチェックを入れてアカウントを作り直す |
| `permission denied for table ...` と出る | 管理者が `supabase/schema.sql` の権限設定（grant の3行）を実行する |
| 選びたい係数が候補にない | 係数の担当者に追加を依頼する |
| 入力を間違えた | データ一覧から行をクリックして修正・削除する |

問い合わせ先：炭素会計担当（担当者名・連絡先をここに書いてください）
